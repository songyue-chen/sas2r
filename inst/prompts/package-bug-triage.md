Reading the facts. A failed dataset output lists its differing columns. For each column, sas_source and generated_code say whether the SAS and the selected R of the upstream programs assign it. Both come from a scan of names in the code: a procedure or macro can create a column that neither names, and unknown means the scan could not decide. passed_through means no generated program assigns the column and none changes columns without naming them. helpers lists the sas2r runtime helpers whose calls name the column or produce its value, and helpers_called lists every helper the upstream programs call. representation_only is measured on the data: yes means the generated and reference values are equal once the conversion named in conversion is applied, so only the stored type differs; no means the values differ as well; not_checked means it was not measured. translator_told is the column type sas2r inferred from the source; a model translating the program was given it. other_differing_columns names further differing columns that are not described, and external_inputs names the input datasets the output depends on. decisions records what sas2r chose for the comparison: how rows were paired, the keys used and where they came from, the tolerance, the file types, and for a date column whether the bundle stored a date or a SAS day number and why. In row_pairing, keys_from is configured when rows were paired on the keys the user set; any other value says where sas2r took the keys from, and heuristic is a guess from column names. keys_refined_by is present when the configured keys repeat and sas2r added a key of its own to tell the rows of a group apart; it says where that key came from. programs gives the origin of each program: rule_based and rule_based_model_unavailable code was written by sas2r's own rules, every other origin by a model. rule_based_units says how much of a program the rules could translate on their own; a model that wrote the program was shown that rule-based R as a reference. runtime_helpers says whether the helpers are the package's own or were patched by a model during the run. shared_patterns lists difference classes that repeat across outputs.

The package-owned steps, each with the sign that points to it and the sign that points away:

1. reading_inputs_and_references. sas2r reads input datasets and references from RDS, XPT and SAS7BDAT files. Points to it: a passed-through column differs in type or in its missing values, the reference and generated file types differ, and the same difference repeats across outputs. Points away: generated code assigns the column, or one output has a plain value difference, which more often means the inputs or the reference were produced differently.
2. facts_given_to_translator. Before translation sas2r gives the model inferred input types, source facts, macro interfaces, the execution order and the documentation of its helpers. Points to it: translator_told or a quoted helper document contradicts the SAS source or the observed types, and the generated R follows that statement. Points away: the supplied fact is correct, or the R does not follow it.
3. rule_based_translation_and_support_files. sas2r's rules translate some programs without a model and write the startup, format and library files of the bundle. Points to it: the faulty statement is in a program whose origin is rule_based or rule_based_model_unavailable, or in a support file, and it does not do what the SAS says. Points away: a model wrote or repaired the program. A mistranslated or omitted SAS statement in model-written code is a translation error, not a package fault.
4. runtime_helpers. Points to it: the generated R calls a helper the way its documentation says, the SAS operation is one the documentation claims to support, the differing column appears in helpers, and a correct helper would have produced the reference result. Points away: the call uses arguments or semantics the documentation does not offer, the helpers were patched during the run, or the helper only carries the column along.
5. write_and_read_conversions. lib_write() and lib_read() convert between R values and stored datasets. Points to it: representation_only is yes, a passed-through column has a type difference, or a date_columns decision contradicts the reference type. Points away: representation_only is no, or generated code assigns the column and gives it the differing type itself.
6. scheduling_and_execution. sas2r orders the programs, defers some and runs the bundle. Points to it: a deferral whose named dependency was available, a program placed before the producer of its input, or a failure raised inside package code. Points away: an error raised by generated code, a missing resource, configuration, or a provider failure.
7. comparison. sas2r pairs rows, applies the tolerance and reports the differences. Points to it: configured keys that are missing from the keys used although no key column differs in type, keys chosen or refined by the name heuristic together with partial row pairing or with differences in many columns the generated code only passes through, a difference the comparison's own stated rules treat as equal, or a failed check that contradicts the facts beside it. Points away: complete row pairing with value differences in columns the generated code assigns.

A repeated difference class is evidence about its cause. When its programs value is independent, the outputs share no upstream program and a shared package step is the likelier cause. When it is shared, the common program can explain the pattern without the package. common_inputs names the external inputs that every one of those outputs reads: a shared input can carry the difference itself, or expose how sas2r reads it.

A dependency deferral records why the scheduler skipped execution. A member marked available in the source-bound library was present and readable as a file. Its contents and generated code still require validation. A deferral in that case may point to a package reconciliation defect.
