Shared source-translation policy (translator, static reviewer, fixer):
- Preserve executable SAS behavior. Reference comparison answers are not a translation specification. Do not infer desired rows, counts or values from a comparison mismatch.
- Preserve source-visible effects, not storage conventions alone. Trailing character padding may differ when nothing observes it; truncation, declared-length operations, concatenation, comparisons and fixed-width exports can make that difference material. Ordinary R NA can represent ordinary SAS missing when its meaning is preserved; special-missing distinctions that affect sorting, grouping or comparisons must survive. A representation difference by itself is neither a defect nor proof of equivalence.
- Canonical identifier case is acceptable only when producers and consumers agree; never change data values for this reason. SAS file handles or template registries need not be reproduced when their used effects are implemented. Fonts and spacing may differ, but required statistics, table sections, meaningful labels, calculations and output artifacts must remain. A PDF that exists is not evidence that all required content exists.
- helper_use lists actual sas2r runtime helper calls only. Ordinary allowed package functions, local functions and selected project functions are not runtime helpers. Metadata normalization must not require rewriting valid code. Call selected dependencies instead of silently copying or replacing their behavior.
- Use the source-owned macro interface. Bare trigger-free text defaults such as 260mm or a+b are text, not R expressions. Unresolved expansion is unknown; NULL or an empty string does not solve it. A bare formal plus missing() handling may be appropriate, but does not certify unsupported omission behavior.
- Missing information is not proof of wrong code. Review finding categories never prove success or cancel independent mechanical/runtime failures.
- Package facts distinguish allowlisting, observed installation/version and documented capability. Inspect supplied selected dependency implementations rather than guess their return types. Missing/truncated bodies establish no return guarantee; an unrelated package fact cannot excuse a defect.
- The initial shared packet has fixed limits. Available dependency code omitted or truncated there is not unavailable source: retrieve the needed SAS and selected R pages with read_dependency_context before claiming missing context. Follow next_offset until the relevant body is complete. If it is genuinely unavailable, keep the uncertainty visible rather than guessing or repeating an unchanged request. Unsupported-capability claims without independent facts remain unverified.
- Translate required effects using native R operations; no SAS execution engine or one-to-one procedure wrapper is required. For GTL/STATGRAPH, SGRENDER and ODS, inspect the template and caller together, then implement the drawing and output file using permitted R graphics packages. Capture and consume any returned drawing function or specification. Metadata without a working consumer, or an unconditional rendering stop where the source defines the behavior, is an incomplete translation. Preserve source statistics and meaningful output content; cosmetic differences may remain for human review.
- Reuse supported operations; never replace banned parse/eval with a handwritten general SQL/WHERE interpreter. A banned implementation may have a simple supported replacement. Never drop required filtering, specialize to observed data, or claim general macro equivalence from an empty-filter example. Keep unsupported behavior explicit.
- A model-only claim that runnable SAS has a syntax error must not become an intentional R stop. SAS macro quoting can mask unmatched punctuation: %str(%() quotes an opening parenthesis. The offline parser is not a SAS compiler. Trace mutated macro values through the next loop condition rather than continue over an assumed original token list. A proposed behavioral reversal needs a concrete source operation and counterexample; a previous or later reviewer opinion is not authority.
- PROC SQL COUNT(DISTINCT x) excludes missing values. Preserve dependency delegation and the dependency's actual return convention. Dataset existence is distinct from readable/populated data; use lib_exists for supported registry members. A valid empty dataset can be correct.
- Numeric display helpers are limited to their documented scope. Field width is not significant-digit count; do not invent a full SAS BEST formatter or change numeric values to make display easier. Cosmetic figure refinement belongs to humans.
- Advisory code-symbol and direct-I/O notices do not establish defects and do not independently authorize repair. Reviewer remains static and read-only; dependency-code retrieval provides no dataset or reference-output access.
- Prefer allowlisted, installed tidyverse packages when their functions express the SAS behavior faithfully; use base R or the bundle helpers when they do not. A base R choice made because no preferred package served the behavior is not a finding; a package idiom that changed SAS behavior is.
- Create an uninitialized DATA-step variable only at the source operation that requires it, using a typed vector such as df$score <- rep(NA_real_, nrow(df)) or df |> dplyr::mutate(score = NA_real_). A value supplied by the next merge input must not be pre-created on another input. Preserve genuine overlapping columns; never drop one merely to bypass sas_merge restrictions. A required input column missing from incompatible data is not permission to invent values or silently replace source filters.
- A repair must implement the required source effect. Removing a stop or call, returning invisible(NULL), or creating metadata without a consumer does not implement that effect. An equivalent implementation in the caller is acceptable when visible and reviewed. If faithful repair is unavailable, return unchanged code with a precise diagnosis and remaining_uncertainty; it remains unresolved within the existing limits.
- A reusable macro's known literal calls and its broader supported behavior are separate claims. Inspect what the source calls actually require, while retaining limitations outside that coverage. Dynamic calls remain unknown; observed input values do not prove a branch unreachable. An unsupported_capability label does not excuse an unnecessary stop or wrong use of an available helper.
- Coordinate selected producer and consumer interfaces: return names, scalar/vector/list shape, lookup rules, missing versus blank values, and caller scope. Do not flatten arbitrary results with unlist(), which can alter names and remove NULL elements. Inspect the selected dependency and preserve source behavior at both ends; do not invent a second global store or compatibility aliases.
- Support review findings with a concrete source/R contradiction and, where practical, a small synthetic trace. Universal numeric-format parity being unproved is uncertainty, not a demonstrated mismatch or proof of correctness. Preserve tiny nonzero arithmetic values and the source stage of display-to-number conversions. An absent scratch macro variable is not automatically global; distinguish existing outer bindings from explicit local shadowing and keep macro values separate from function names.
- Nonlocal-assignment notices are advisory only: <<- may target a parent local environment, and source %GLOBAL may justify global state. Notices alone do not authorize repairs.
- lib_members("work") lists ordinary supported registry members for runtime list expansion; lib_delete("work", lib_members("work")) is valid only when source requests those members and deletion restrictions allow it. Listing does not authorize deletion of separate input files or expand views/ranges/name literals. Library contents remain outside authoring-agent access.
