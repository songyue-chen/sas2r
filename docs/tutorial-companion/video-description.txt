Learn how to use sas2r in RStudio for an AI-assisted SAS-to-R migration. This walkthrough covers provider choice, OpenAI setup, API credits, .Renviron, _sas2r.yml, offline input preflight, connection probing, console logs, translation, a real translator–reviewer–fixer sequence, output inspection, and independent R-code export.

This update uses sas2r 0.6.0 beta from GitHub PR #65, based on merged develop. It is not the current CRAN release. Install the tested commit to reproduce it:
install.packages(c("remotes", "ellmer", "pdftools"))
remotes::install_github("songyue-chen/sas2r", ref = "22b34abc27f0a73b679f124f51ce9cee4fa39aef")
Restart R after installation if sas2r was already loaded.

sas2r uses the ellmer R package to interact with large language models. Choose among sas2r's supported providers, including OpenAI, Anthropic (Claude), Google Gemini (Gemini API), and DeepSeek. Cloud integrations for enterprise deployments include Amazon Bedrock on AWS, Azure OpenAI on Microsoft Azure, and Google Cloud through the Vertex AI API. This tutorial uses OpenAI as one example; provider-specific credentials, configuration, and model access are required.

Configuration: copy the 11 commented OpenAI YAML lines at the end of demo.R into the same project _sas2r.yml, below outputs. Remove only the leading "# " from each pasted line and preserve the remaining indentation. Keep libraries and outputs; align llm at the same top level. Update an existing llm section instead of duplicating it, then save. Keep the API key in .Renviron. Script excerpts display their actual line numbers.

This tutorial uses reconstructed interfaces, synthetic data, Sarah's synthetic narration, and captions. The shown live OpenAI run used the same runtime and prompts as the pinned 0.6.0 beta commit, ellmer 0.5.0, R 4.4.0, and gpt-5.6-luna. The final tested run reached migration_ready without repairs. Review, execution, dataset checks, source-derived column order, and PDF text and demo geometry checks passed. The actual PDF was also visually inspected for readable columns and compact row spacing. The fixer segment is explicitly labeled as a separate earlier beta run, where the reviewer identified a missing Obs column and the fixer restored it. Actual AI runs can differ.

Saved PDF: <working-directory>/migration-output/<run_id>/outputs/tlf/table1.pdf
There is no additional outputs/ beneath tlf/. The generated report writer uses sas_output_path() to create the directory under the run's output root and sas_print_table() for aligned, paginated plain listings. AVAL_FLAG is the first dataset column because LENGTH precedes SET in the SAS source.

After exporting, use source("run-export.R") in a fresh R session from the tutorial project. It runs exported-r/run.R without sas2r loaded or an AI connection. Generated reports go to exported-r/output/tlf/. The runtime creates the directory; the companion script no longer needs a folder workaround. Exported dataset, column-order, and PDF checks passed. Manual execution does not update the original migration report or validation status.

A successful probe checks a structured ping, not a complete migration. No independent SAS reference output is supplied, so execution and tutorial checks do not establish SAS equivalence. Inspect PDF formatting as well as content: this example does not establish SAS PROC PRINT layout equivalence.

The helper and demo geometry checks cover plain listings. They do not validate arbitrary PDF layouts or certify SAS styling equivalence. The release notes remain under 0.6.0 beta; main is unchanged.
